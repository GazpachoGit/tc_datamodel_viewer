# Дизайн утилиты

## Общий подход

- **DG1.** Утилита на Python преобразует XML-файлы из одной папки в общий
  PlantUML-файл согласно [требованиям](./requirements.md) и
  [маппингу](./mapping.yaml).
- **DG2.** Этапы обработки: чтение входных файлов и маппинга, построение
  общей модели, генерация текста PlantUML и запись результата.

## Вход и маппинг

- **DI1.** Командная строка принимает путь к папке. Обрабатываются только
  XML-файлы непосредственно в ней.
- **DI2.** XML разбирается с учётом namespace Teamcenter. Для разбора можно
  использовать `xml.etree.ElementTree` из стандартной библиотеки Python.
- **DI3.** Маппинг загружается из YAML; предлагается использовать PyYAML и
  безопасную загрузку через `safe_load`. При преобразовании `attributeType`
  выбирает правило с полями `type`, `array_flag` и необязательным `chars`.
- **DI4.** Предлагается обрабатывать файлы в стабильном порядке по имени, а
  элементы внутри каждого файла — в порядке их появления. Это определяет,
  какое определение считается первым при повторениях.

## Общая модель

- **DM1.** Модель содержит классы, доступные по имени. Класс хранит имя,
  имя родителя, атрибуты по имени и признак того, что обработано его
  первое определение `TcClass`. Этот признак позволяет сохранить выбор
  первого родителя, в том числе когда он отсутствует.
- **DM2.** Атрибут хранит имя, преобразованный тип, признак массива и
  непустые характеристики с их XML-именами и значениями. Исходный XML-тип
  используется при выборе маппинга, но в модели атрибута не сохраняется.
- **DM3.** Класс, созданный как родитель или цель `TcAttributeAttach`,
  не считается определённым через `TcClass`. При первом определении
  `TcClass` существующий класс дополняется, его родитель фиксируется,
  а признак определения устанавливается.

## Обработка определений

- **DP1.** Для первого определения `TcClass` утилита создаёт или дополняет
  класс, при необходимости создаёт родительский класс и добавляет
  атрибуты. При пустом или отсутствующем `parentClassName` родительская
  связь не создаётся.
- **DP2.** Для `TcAttributeAttach` утилита находит или создаёт целевой класс
  по `className` и добавляет его атрибуты.
- **DP3.** Из повторных определений `TcClass` добавляются атрибуты без
  ошибки о дублировании класса. Родитель остаётся таким, как в первом
  определении, даже если там он не указан. Повторный атрибут в том же
  классе пропускается с ошибкой, содержащей имя класса и атрибута;
  обработка продолжается, первый атрибут сохраняется.
- **DP4.** Для нового атрибута тип берётся из `type`; `array_flag` указывает
  на XML-атрибут признака массива; `chars` перечисляет XML-атрибуты для
  вывода. Отсутствующие и пустые характеристики не добавляются в модель.

## Генерация и запись

- **DR1.** Собственные функции `render_attribute`, `render_class` и
  `render_model` формируют текст PlantUML из модели. Генератор не требует
  библиотеки для построения диаграмм.
- **DR2.** Генератор выводит классы, атрибуты и связи наследования между
  `@startuml` и `@enduml`. Имена и значения должны корректно представляться
  в PlantUML; правила экранирования следует проверить при реализации.
- **DR3.** После обработки входных файлов результат записывается в исходную
  папку с отметкой времени с точностью до секунды. При совпадении имени
  существующий файл перезаписывается.

## Проверка

- **DV1.** Проверить применение маппинга, XML namespace, создание и
  дополнение классов, объединение повторных определений с сохранением
  первого родителя, повторные атрибуты, `TcAttributeAttach` и связи
  наследования.
- **DV2.** Проверить генерацию примера из требований и сквозной сценарий с
  несколькими XML-файлами. Корректность синтаксиса PlantUML проверить
  локальным рендерером.

## Вопросы

- **DQ1.** Требования к обработке некорректного XML, неизвестных типов,
  отсутствующих обязательных значений и недоступного маппинга ещё не
  согласованы.
- **DQ2.** Поведение при пустой входной папке и правила разрешения особых
  символов в именах и значениях требуют уточнения.
